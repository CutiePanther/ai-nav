## 为什么要切分

- 模型上下文有限，不能整篇塞进去；
- 检索粒度：切得合适才能精准召回「相关的那一小段」；
- 向量质量：过长的文本 embedding 会「稀释」主题。

## 常见策略

1. **固定长度切分**：按固定 token 数切，简单但可能把句子/语义切断；
2. **递归字符切分**：按段落 → 句子 → 词的优先级递归切，尽量落在自然边界；
3. **语义切分**：用 embedding 相似度找「语义断点」，让每块语义完整；
4. **结构感知切分**：按文档结构（标题、表格、代码块）切，适合 Markdown/HTML。

## 关键参数

- **chunk 大小**：几百到上千 token 不等，依文档类型而定；
- **overlap（重叠）**：块与块之间保留一小段重叠，避免把关键信息切在边界上；
- **元数据保留**：保留标题、章节等元信息，便于检索和引用。

## 面试加分点 / 追问方向

- 「切分质量决定 RAG 上限」——切分不好，后面检索和生成都白搭；
- 不同文档（法律条款 vs 代码 vs 对话记录）需要不同切分策略，没有银弹。
