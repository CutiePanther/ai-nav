## 核心概念

用户的提问方式与知识库文档的表述往往差异很大，直接检索可能召回不到真正相关的内容。**查询侧优化**在检索之前改造 Query，把「提问空间」映射到更贴近「文档空间」的表达，是 RAG 优化中投入小、收益明显的一环。

## 关键要点 / 原理

1. **Query Rewriting**：用轻量 Prompt 把口语化、模糊或含多个子问题的问题改写为规范、关键词更精准的检索式；
2. **Multi-Query**：让 LLM 从多个角度生成 3-5 个变体查询分别召回，合并去重后覆盖同一需求的不同表达；
3. **HyDE**：先让 LLM 凭空生成一段「假想答案（疑问句转陈述句）」，再用其向量去检索——跨越提问与文档的语义鸿沟；
4. **子问题分解**：复杂多步问题拆解成若干原子子问题分别检索再聚合；
5. **取舍**：这些手段每次增加一次 LLM 调用与延迟，需结合命中率、使用量与成本权衡是否常开。

## 延伸 / 追问方向

- Query Rewriting 相比对 Embedding 模型做领域微调的成本差异；
- Multi-Query 变体数量越多越好吗？
- 查询改写与混合检索、Rerank 三者如何配合；
- 什么情况下改写反而会损伤精度（如语义本就明确的问题）。

## 面试加分点

- 能点出 HyDE 的核心洞察：关键不在假想答案内容正确，而在于它把查询映射到了文档的「陈述句」风格空间。
