## 对比

| 维度 | 闭源模型 | 开源模型 |
| --- | --- | --- |
| 能力 | 通常更强 | 追赶中，顶尖已接近 |
| 成本 | API 按量计费 | 一次性硬件 + 运维 |
| 数据隐私 | 数据出域 | 可私有化部署 |
| 可控性 | 黑盒 | 可微调、可改 |
| 运维 | 免运维 | 需自己部署 |

## 选型原则

- **快速验证 / 能力优先** → 闭源 API，几行代码就能跑；
- **数据敏感 / 合规要求** → 开源私有化部署；
- **需要深度定制（微调、改架构）** → 开源；
- **成本敏感、调用量大** → 自部署开源模型（规模大时更省）；
- **混合策略**：能力要求高的用闭源，私有数据场景用开源，是很多公司的常态。

## 面试加分点 / 追问方向

- 能说清「总拥有成本」：API 按 token 计费 vs 自部署的 GPU 硬件 + 人力成本，存在规模拐点；
- 开源的「可微调」是闭源难以替代的核心价值。
