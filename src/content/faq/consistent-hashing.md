## 为什么需要一致性哈希

普通取模哈希 `hash(key) % N` 在**节点数量变化**时，几乎导致所有 key 重新映射到不同节点，数据大规模迁移。一致性哈希目标就是**尽量少受节点增删影响**。

## 核心原理

- **哈希环**：把整个哈希值域组织成首尾相接的环（0 ~ 2³²-1），节点按 `hash(IP)` 落到环上；
- **数据寻址**：`key` 沿环**顺时针**找到的第一个节点即为目标节点；
- **节点增减影响局部**：新增/删除一个节点，只会影响该节点环前侧的一小段数据，其余 key 不动；
- **虚拟节点**：一个物理节点在环上放多个「虚拟节点」，让数据在节点间分布更均匀，缓解哈希倾斜；
- **经典用法**：一致性哈希最早用于缓存的分布式方案（如 Memcached 客户端），现广泛用于负载均衡、Redis Cluster 槽位、分布式存储。

## 面试加分点 / 追问方向

- **为什么不直接用取模哈希**：节点变化会导致绝大多数 key 重新映射，引发缓存雪崩式迁移；
- **如何降低数据倾斜**：增加虚拟节点数量、让节点哈希更均匀；
- **和其他方案对比**：Redis Cluster 用的是 16384 个槽（slot）而不是纯一致性哈希，要能说出两者的关系；
- **工程实现**：Rendezvous Hashing（最高随机权重哈希）是另一类一致性分配方案，可作延伸。
