## 核心思想

RAG = **检索（Retrieval）+ 生成（Generation）**。让 LLM "先查资料、再作答"，而不是凭训练记忆硬答——把外部知识检索出来作为上下文，喂给模型生成答案。

## 为什么要用 RAG

LLM 存在三个难以靠自身解决的短板：

- **幻觉**：模型学到的是语言分布，不是事实真值，容易一本正经地编造；
- **时效性**：训练数据有截止时间，跟不上最新知识；
- **私有知识**：企业内部文档不在训练集，无法直接问答。

RAG 用"外部检索 + 引用来源"同时缓解以上三点，还额外带来**可溯源、可更新**的好处（换知识库即可更新知识，无需重训模型）。

## 完整链路

1. **文档切分**：把长文档切成 chunk（片段）；
2. **向量化入库**：用 embedding 模型把 chunk 变成向量，存入向量库；
3. **查询检索**：用户问题也向量化，用 ANN 检索出 top-k 最相似 chunk；
4. **拼接生成**：把检索到的内容作为上下文拼进 prompt，交给 LLM 生成答案。

## 面试加分点

- **RAG vs 微调**：RAG 改的是"输入"，参数不动、成本低、可实时更新；微调改的是"参数"，把知识内化到权重里，成本高但推理更省 prompt。
- **召回优化**：混合检索（向量 + BM25 关键词）+ Rerank 重排，是提升召回质量的主流手段。
- **chunk 大小**：过小丢语义上下文，过大稀释相关度，需按文档类型调优。
