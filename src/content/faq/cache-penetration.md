## 三者的本质区别

| 问题 | 触发场景 | 后果 |
| --- | --- | --- |
| 缓存穿透 | 恶意/大量查询**根本不存在**的数据 | 每次请求都落到 DB，可能拖垮数据库 |
| 缓存击穿 | **某个热点 key** 过期瞬间，大量并发打到 DB | 数据库瞬时压力剧增 |
| 缓存雪崩 | **大量 key** 同一时刻过期，或缓存服务宕机 | 数据库被海量请求击垮 |

## 应对方案

- **穿透**：
  1. **布隆过滤器**：快速判断 key 是否存在，不存在直接拦截；
  2. 缓存空值：对不存在的结果也缓存一个短过期时间的空值；
  3. 参数校验：非法参数直接拒绝。
- **击穿**：
  1. **互斥锁/分布式锁**：只有一个请求去查库并回填，其余等待；
  2. 热点 key 逻辑过期 + 后台异步刷新；
  3. 热点数据**永不设置过期**，用更新机制替换。
- **雪崩**：
  1. **过期时间加随机值**，避免同时失效；
  2. 缓存集群高可用 + 多级缓存；
  3. 限流降级、熔断，保护数据库。

## 面试加分点 / 追问方向

- **布隆过滤器的原理与缺点**：多个哈希函数标记位图，空间效率高，但有误判（判存在可能不准）且不支持删除；
- **热点 key 发现**：通过监控、访问日志或代理层统计识别热点；
- **与击穿的组合**：实际生产往往是「热点 + 集中过期」叠加，需要多层防护。
