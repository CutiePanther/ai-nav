## 核心区别

| 维度 | HTTP | HTTPS |
| --- | --- | --- |
| 加密 | 明文传输 | TLS 加密（传输层安全） |
| 端口 | 80 | 443 |
| 安全性 | 易被窃听、篡改、冒充 | 机密性 + 完整性 + 身份认证 |
| 握手 | 简单 | 多一轮证书校验与非对称/对称密钥协商 |
| 性能 | 更快 | 有加解密与握手开销（HTTP/2 后差距缩小） |

## HTTPS 的 TLS 握手流程（简化）

1. 客户端发 ClientHello（支持的加密套件、随机数）；
2. 服务端回 ServerHello + **数字证书**（含公钥）+ 随机数；
3. 客户端用 CA 根证书**验证证书合法性**；
4. 客户端生成预主密钥，用服务端公钥加密发送；
5. 双方各自计算出**会话密钥**（对称密钥）；
6. 之后用会话密钥对称加密通信（对称加密快）。

## 为什么非对称加密只用于握手

非对称加密（RSA/ECDHE）计算量大、速度慢，不适合加密海量数据；所以用它安全地交换一个对称密钥，之后用 AES 等对称加密传输正文。

## 面试加分点 / 追问方向

- **中间人攻击**：HTTPS 靠证书链防 MITM，若用户信任了伪造根证书则仍可被劫持；
- **HTTP/2 与 HTTPS**：浏览器强制 HTTP/2 走 HTTPS（h2），多路复用大幅降低握手与队头阻塞开销；
- **TLS 1.3 优化**：握手从 2-RTT 降到 1-RTT，废弃不安全算法，更安全更快。
