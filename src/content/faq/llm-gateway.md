## 为什么需要网关

- 多模型来源：OpenAI、Anthropic、DeepSeek 等 API 格式各异，直接对接很痛苦；
- 统一治理：限流、鉴权、配额、审计需要集中管理；
- 成本与质量：需要按成本/延迟/能力做智能路由和 fallback。

## 核心能力

1. **统一接口**：屏蔽厂商差异，业务方只对接网关一套 API；
2. **路由策略**：按模型能力、成本、延迟路由到最合适的模型，支持自动降级/重试；
3. **限流与配额**：按用户/应用做速率限制与额度控制；
4. **缓存**：复用相同请求结果，降本；
5. **可观测**：记录每次调用的 token、成本、延迟，做统计与告警。

## 设计要点

- 无状态、可水平扩展；请求日志异步落库；
- 路由策略可插拔；支持灰度切换模型；
- 与提示词缓存、评估平台打通。

## 面试加分点 / 追问方向

- 说清「网关」和「模型 API」的分层关系；
- 可用 LiteLLM、Portkey 等开源网关理解落地细节。
