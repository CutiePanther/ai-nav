## 并发事务的三大问题

- **脏读**：读到其他事务**未提交**的数据，回滚后数据就「没了」；
- **不可重复读**：同一事务内两次读同一条记录，因其他事务**提交更新**而结果不同；
- **幻读**：同一事务内两次范围查询，因其他事务**插入新记录**而出现「多出来的行」。

## 四种隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
| --- | --- | --- | --- |
| 读未提交（RU） | 可能 | 可能 | 可能 |
| 读已提交（RC） | 解决 | 可能 | 可能 |
| 可重复读（RR，MySQL 默认） | 解决 | 解决 | 基本解决（MySQL 通过读加锁特别处理） |
| 串行化（Serializable） | 解决 | 解决 | 解决（但并发极低） |

## MVCC：多版本并发控制

- **核心**：每行记录带隐藏列（事务 ID、回滚指针），更新时**不覆盖原值**而是生成新版本并连成版本链；
- **ReadView 快照**：开启事务时生成可见性视图，判断哪些版本对当前事务可见，实现**不加锁的快照读**；
- **InnoDB 的 RR 下**：`ReadView` 在**第一次读时创建**并可跨语句复用，从而解决不可重复读与幻读（配合 `next-key lock`）；
- **RC 与 RR 的区别**：RC 每条 SELECT 都生成新 `ReadView`，RR 复用首次生成的 `ReadView`。

## 面试加分点 / 追问方向

- **快照读 vs 当前读**：`SELECT ... FOR UPDATE / LOCK IN SHARE MODE` 走当前读（读最新版本并加锁），普通 SELECT 走快照读；
- **MVCC 只解决快照读的幻读**：当前验用的插入仍可能幻读，需靠 `next-key lock`；
- **回滚段与 undo log**：MVCC 的版本链依赖 undo log，长事务会导致 undo log 膨胀；
- **隔离级别如何选择**：RC 常配合 binlog 行格式使用，RR 是 MySQL 默认，两者的写入锁范围不同。
