## 核心概念

LLM 按 token 计费，且每轮会重新计算整个上下文，因此应用的**成本随上下文长度与调用量**整体上涨。成本优化本质是「减少重复计算 + 减少无效 token + 按需选择模型」。

## 关键要点 / 原理

1. **缓存复用**：提示词缓存/Prefix Cache（复用相同前缀的 KV）、语义缓存（复用相似请求结果）是降本最有效的两招；
2. **控制上下文**：滑动窗口截断、摘要压缩、向量检索召回历史，避免过度填充长上下文；
3. **模型路由**：按任务复杂度、成本、延迟路由——简单任务用便宜小模型，复杂任务才用旗舰模型；
4. **吞吐与批量**：连续批处理（Continuous Batching）提升 GPU 利用率，摊薄单请求成本；
5. **量化选型**：INT8/INT4 降低显存与带宽需求，压缩单次推理开销；
6. **规避重复调用**：结构化输出、批量非实时任务合并，避免一需求多次往返。

## 延伸 / 追问方向

- 如何把「字数」换算成 token（1 汉字 ≈ 0.6~1.5 token）做预算预估；
- 提示词缓存与语义缓存哪个降本地见效更快；
- 成本与质量的权衡用哪些指标监控（单位 token 成本、每千次提问成本）；
- 自建推理 vs 调用 API 的成本对比要考虑哪些（吞吐、利用率、人力运维）。
