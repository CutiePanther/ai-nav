## 三者本质区别

| 维度 | 提示词工程 | RAG | 微调 |
| --- | --- | --- | --- |
| 改动对象 | 输入 | 上下文 | 模型参数 |
| 成本 | 极低 | 低 | 高 |
| 知识更新 | 即时 | 即时（换库即可） | 需重训 |
| 可解释/溯源 | 无 | 有引用来源 | 无 |
| 适用 | 日常调优 | 私有/时效知识 | 风格/格式/领域能力 |

## 选型原则

- **先提示词**：能靠 prompt 解决的，绝不微调——最便宜、最灵活；
- **知识类 → RAG**：知识频繁变化、需要引用来源、数据超出上下文时用 RAG；
- **行为/风格类 → 微调**：想让模型稳定输出某种格式、语气、领域习惯，且知识相对静态时用微调；
- **组合**：常见做法是「微调改行为 + RAG 补知识」，提示词贯穿始终。

## 面试加分点 / 追问方向

- 能给出具体决策判断：「客服要实时查订单 → RAG」「要让模型按公司口吻回复 → 微调」；
- 微调的隐性成本：数据标注、训练资源、版本管理与回归评测。
