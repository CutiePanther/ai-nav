## 核心概念

LLM 调用贵且慢，很多请求本质重复或高度相似。**语义缓存**在普通「完全命中」基础上，用向量库对查询做相似度召回：相似度超过阈值即视为命中，直接返回缓存结果而不调用模型，从而大量省成本、降延迟。

## 关键要点 / 原理

1. **命中判定**：把查询 embedding 后到缓存向量库检索，余弦相似度 > 阈值（如 0.9）即命中，阈值决定「误伤」与「漏命中」的平衡；
2. **存储**：常用 Redis（键值/相似度）、也可用 Qdrant/Redis Semantic Cache 等；
3. **一致性**：知识库或 Prompt 变更是语义缓存失效的主因，需结合 TTL、显式失效、版本化 key；
4. **降级兜底**：缓存挂了不能影响主链路——命中失败应放行到模型而非报错；
5. **边界**：动态/个性化内容（含用户信息、随机数）不适合语义缓存，可只对静态部分做前缀命中。

## 延伸 / 追问方向

- 语义缓存与「提示词/Prefix Cache」的区别（语义 vs 前缀级 KV 复用）；
- 阈值设置过高/过低各有什么后果；
- 知识更新后如何保证缓存不返回过期结果；
- 缓存失效时要考虑哪些降级策略。

## 面试加分点

- 能区分「语义缓存（应用层复用结果）」与「前缀缓存（KV Cache 复用计算）」两个层级，说明各自收益点。
