## 核心差异

| 维度 | TCP | UDP |
| --- | --- | --- |
| 是否面向连接 | 是（三次握手建立连接） | 否（无连接） |
| 可靠性 | 可靠（确认、重传、排序） | 不可靠（尽力而为） |
| 传输方式 | 面向字节流 | 面向报文 |
| 数据边界 | 无边界 | 有边界 |
| 传输效率 | 较低（头部 20B+，握手开销） | 较高（头部仅 8B） |
| 拥塞控制 | 有 | 无 |
| 适用场景 | 文件传输、网页、数据库 | 音视频、实时游戏、DNS 查询 |

## 关键要点

- **TCP 的可靠性靠一系列机制保证**：序号与确认（ACK）、超时重传、滑动窗口流量控制、拥塞避免；
- **UDP 常用在可容忍少量丢包而要求低延迟低开销的场景**，如直播、VoIP、DNS、QUIC 的底层；
- **选择依据**：先判断是否需要「可靠有序」，再看对延迟和头部开销的敏感度。

## 面试加分点 / 追问方向

- **TCP 一定比 UDP 慢吗**：不一定，慢是「可靠」机制的代价，同时受网络环境影响；
- **哪些协议基于 UDP**：DNS、DHCP、RTP、QUIC（基于 UDP 但自带可靠层）；
- **UDP 想可靠怎么办**：在应用层自实现重传与排序，或直接用 QUIC；
- **连接状态**：TCP 是面向字节流的可靠流协议，UDP 是面向报文的不可靠数据报协议。
