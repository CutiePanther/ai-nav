## 核心作用

1. **异步解耦**：生产者与消费者不直接依赖，一方故障不影响另一方；
2. **削峰填谷**：突发流量先入队，消费者按自身能力消费，保护下游；
3. **顺序消息**：通过分区/队列保证局部有序；
4. **广播与分发**：一条消息被多个消费者订阅（如日志同步、缓存失效）。

## 主流 MQ 选型对比

| 特性 | Kafka | RocketMQ | RabbitMQ |
| --- | --- | --- | --- |
| 吞吐 | 极高（百万级） | 高（十万级） | 中等 |
| 延迟 | 毫秒级 | 毫秒级 | 微秒级（小消息） |
| 消息模型 | 分区 + 消费组 | 主题 + 队列 | Exchange + Queue |
| 可靠性 | 高（多副本） | 高（事务/延迟消息） | 高（ACK 机制） |
| 典型场景 | 日志、流处理、大数据 | 电商交易、延迟消息 | 企业级路由、低延迟 |

## 面试加分点 / 追问方向

- **如何保证消息不丢**：生产端确认机制（ACK）+ Broker 持久化与副本 + 消费端手动提交 offset；
- **如何保证不重复消费**：消费端做幂等（唯一 ID + 去重表 / 数据库唯一约束）；
- **消息堆积怎么办**：增加消费者、提升消费速度、排查下游瓶颈，必要时扩容分区。
